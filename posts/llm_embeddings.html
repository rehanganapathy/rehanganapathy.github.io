Embeddings for Text: Foundations, Methods, and Applications

Author: Rehan Ganapathy · Date: September 1, 2025

Abstract

Embeddings are the semantic backbone of modern natural language processing (NLP). They transform raw text into dense vectors that capture similarity, meaning, and context, enabling machines to process language effectively. From early statistical methods like TF–IDF to neural embeddings such as Word2Vec, and later to contextual embeddings from transformers (BERT, GPT), embeddings have evolved into powerful representations that drive state‑of‑the‑art large language models (LLMs). This article presents a comprehensive overview of embeddings: their mathematical foundations, evolution, implementations with code, diagrams, and applications.

1. Introduction

Raw text cannot be directly understood by computers. Early representations such as one‑hot encoding and bag‑of‑words (BoW) allowed text to be stored as vectors, but these lacked semantic meaning: synonyms, analogies, and polysemy were ignored. Embeddings solve this by mapping text into dense, low‑dimensional vector spaces where geometry reflects meaning: similar words appear close, analogies can be represented linearly, and context modifies representation.

2. From Statistical to Neural Embeddings

The evolution of vector representations spans three major phases: (i) statistical term weighting (TF–IDF, LSA), (ii) neural predictive embeddings (Word2Vec, GloVe, FastText), and (iii) contextual representations learned by transformers (ELMo, BERT, GPT). Each step improved semantic fidelity and downstream utility.

2.1 Statistical Embeddings (TF–IDF)

Formula TF–IDF assigns weight to term t in document d as

\[\text{TF}(t,d) = \frac{\text{count}(t,d)}{\text{total terms in } d},\qquad \text{IDF}(t) = \log \frac{N}{1+n_t}\]

\[\text{TF–IDF}(t,d) = \text{TF}(t,d)\times \text{IDF}(t).\]

Intuition. Terms frequent in a document but rare in the corpus get higher weight, improving retrieval and keyword extraction. However, TF–IDF vectors are sparse and ignore semantics (e.g., cat vs dog).

Example: TF–IDF on Tiny Shakespeare

# Load the dataset
with open("tinyshakespeare.txt", "r") as file:
    corpus = file.read()

print(f"Text corpus includes {len(corpus.split())} words.")

# Split into 10 documents
N = len(corpus) // 10
documents = [corpus[i:i+N] for i in range(0, len(corpus), N)]
documents = documents[:-1]  # drop the last residue

from sklearn.feature_extraction.text import TfidfVectorizer

# Create TF–IDF embeddings
vectorizer = TfidfVectorizer()
embeddings = vectorizer.fit_transform(documents)
words = vectorizer.get_feature_names_out()

print(f"Word count: {len(words)} e.g.: {words[:10]}")
print(f"Embedding shape: {embeddings.shape}")
# Output:
# Text corpus includes 202651 words.
# Word count: 11446 e.g.: ['abandon' 'abase' 'abate' 'abated' 'abbey' 'abbot' 'abed' 'abel' 'abet' 'abhor']
# Embedding shape: (10, 11446)

2.2 Neural Embeddings (Word2Vec)

Idea Learn word vectors by solving a prediction task over local context windows. Two architectures are standard: CBOW (predict target from context) and Skip‑Gram (predict context from target). These dense vectors exhibit striking linear structures (e.g., analogies).

Analogy Demo with Pretrained Google News Vectors

import gensim

# Load pretrained Word2Vec embeddings (3M vocab, 300 dims)
model = gensim.models.KeyedVectors.load_word2vec_format(
    'GoogleNews-vectors-negative300.bin.gz',
    binary=True
)

print(f"The embedding size: {model.vector_size}")
print(f"The vocabulary size: {len(model)}")

# Vector arithmetic: italy - rome + london = ?
print(model.most_similar(positive=['london', 'italy'], negative=['rome']))

# Vector arithmetic: doctor - man + woman = ?
print(model.most_similar(positive=['woman', 'doctor'], negative=['man']))
# Example output:
# [('england', 0.574), ('europe', 0.537), ('liverpool', 0.514), ...]
# [('gynecologist', 0.709), ('nurse', 0.648), ('doctors', 0.647), ...]

CBOW (Continuous Bag‑of‑Words): Objective & Flow

Given context words within a window around position t, CBOW predicts the center word \(w_t\). Let \(C\) be the number of context tokens used. With input embeddings \(v_w\) and output embeddings \(u_w\), CBOW maximizes:

\[\log p(w_t\mid w_{t-C},\dots,w_{t-1},w_{t+1},\dots,w_{t+C}) = \log \text{softmax}(u_{w_t}^{\top}\, \bar{v}),\]

where \(\bar{v} = \frac{1}{2C}\sum_{c\in\mathcal{N}(t)} v_{w_c}\) is the average of context vectors. In practice, negative sampling replaces the full softmax to reduce cost:

\[\mathcal{L}_{\text{CBOW}} = -\log \sigma(u_{w_t}^{\top}\bar{v}) - \sum_{i=1}^{k} \mathbb{E}_{w_i\sim P_n}\,\log \sigma(-u_{w_i}^{\top}\bar{v}).\]

Diagram: CBOW (predict center from context)

Context window (size C)

  w_{t-2}    w_{t-1}             w_{t+1}    w_{t+2}
     |           |                   |           |
 [Lookup]    [Lookup]             [Lookup]   [Lookup]
     |           |                   |           |
     v           v                   v           v
  v_{t-2}     v_{t-1}             v_{t+1}    v_{t+2}
       \        |                    |        /
        \       |                    |       /
             [Average / Sum]  -->  \bar{v}
                     |
                 [Linear]
                     |
                 [Softmax]
                     |
                predict w_t

Notes. CBOW is fast and stable on small datasets; averaging context smooths noise. It can underemphasize rare words compared to Skip‑Gram.

Skip‑Gram: Objective & Flow

Skip‑Gram inverts CBOW: given center word \(w_t\), predict each context word \(w_c\in\mathcal{N}(t)\). The (negative sampling) loss sums over contexts:

\[\mathcal{L}_{\text{SG}} = -\sum_{c\in\mathcal{N}(t)} \big[\log \sigma(u_{w_c}^{\top} v_{w_t}) + \sum_{i=1}^{k} \mathbb{E}_{w_i\sim P_n}\, \log \sigma(-u_{w_i}^{\top} v_{w_t}) \big].\]

Diagram: Skip‑Gram (predict context from center)

Center word at position t

               w_t
                |
            [Lookup]
                |
              v_{t}
        /      |       \
       /       |        \
[Linear]   [Linear]   [Linear]
   |          |           |
[Softmax] [Softmax]   [Softmax]
   |          |           |
 predict    predict     predict
 w_{t-2}    w_{t-1}     w_{t+1}  ...

Trade‑off. Skip‑Gram better captures rare words and fine‑grained semantics but is slower since it predicts multiple targets per center token.

2.3 Contextual Embeddings

Why Static embeddings assign one vector per word type, failing on polysemy (e.g., bank as river edge vs. financial institution) and context sensitivity. How Transformers compute context‑conditioned vectors via self‑attention, so each token’s embedding depends on all others in the sequence.

Self‑Attention (single head)

For queries \(Q\), keys \(K\), values \(V\):

\[\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V.\]

Diagram: Transformer Self‑Attention (token‑wise)

Tokens → [Embed + Positional Encoding] → Transformer Layers

  x_1   x_2   x_3  ...  x_T
   |     |     |         |
  e_1   e_2   e_3  ...  e_T   (input embeddings)
   |     |     |         |
  ┌───────────────────────────┐
  |  For each layer (multi‑head self‑attention + MLP):
  |   Q = eW_Q,  K = eW_K,  V = eW_V
  |   A = softmax(QKᵀ/√d_k)
  |   h = A V    (per head, then concatenated)
  |   e ← LayerNorm(e + h) → MLP → LayerNorm
  └───────────────────────────┘
   |     |     |         |
  h_1   h_2   h_3  ...  h_T   (contextual embeddings)

Example: BERT Contextual Embeddings

from transformers import AutoTokenizer, AutoModel
import torch

# Load pre-trained BERT
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")

sentence = "The bank will not lend money near the river bank."
inputs = tokenizer(sentence, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

token_embeddings = outputs.last_hidden_state
print(token_embeddings.shape)  # (batch, seq_len, hidden_dim)

sentence_embedding = token_embeddings[:,0,:]  # [CLS]
print(sentence_embedding.shape)
# e.g., torch.Size([1, 12, 768]) and torch.Size([1, 768])

Example: Sentence‑BERT (sentence‑level similarity)

from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("all-MiniLM-L6-v2")

sentences = [
    "A man is playing guitar.",
    "Someone is performing music.",
    "The dog is sleeping on the floor."
]

embeddings = model.encode(sentences, convert_to_tensor=True)

print("Similarity (music vs guitar):",
      util.cos_sim(embeddings[0], embeddings[1]).item())
print("Similarity (music vs dog):",
      util.cos_sim(embeddings[0], embeddings[2]).item())
# ~0.82 vs ~0.21

3. Embeddings in Large Language Models (LLMs)

LLMs use an input embedding layer (token lookup table) to initialize token vectors, and then transform them through multiple layers into contextual embeddings (hidden states). The input embedding matrix itself can be extracted and reused directly for tasks like similarity search.

3.1 Extracting & Saving Input Embeddings (Hugging Face)

import torch
from transformers import AutoTokenizer, AutoModel

tokenizer_name = "deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B"
model_name = tokenizer_name

# Load tokenizer & model
tokenizer = AutoTokenizer.from_pretrained(tokenizer_name)
tokenizer.add_special_tokens({'pad_token': '[PAD]'})
model = AutoModel.from_pretrained(model_name)

# Extract embeddings layer
embeddings = model.get_input_embeddings()
print(f"Extracted Embeddings Layer: {embeddings}")

# Save weights (shape: [vocab_size, embedding_dim])
torch.save(embeddings.state_dict(), "embeddings_qwen.pth")

3.2 Loading Pretrained Embeddings into a Lightweight Model

import torch
import torch.nn as nn
from transformers import AutoTokenizer

class EmbeddingModel(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
    def forward(self, input_ids):
        return self.embedding(input_ids)

vocab_size = 151936
dimensions = 1536
model = EmbeddingModel(vocab_size, dimensions)

saved = torch.load("embeddings_qwen.pth")
if 'weight' not in saved:
    raise KeyError("No 'weight' key in saved embeddings")

embeddings_tensor = saved['weight']
if embeddings_tensor.size() != (vocab_size, dimensions):
    raise ValueError(f"Expected ({vocab_size}, {dimensions}), got {embeddings_tensor.size()}")

model.embedding.weight.data = embeddings_tensor
model.eval()

tokenizer = AutoTokenizer.from_pretrained("deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B")

3.3 Similarity Search over the Embedding Space

import torch

# Cosine-similarity search against the entire vocab matrix
def find_similar_embeddings(target_embedding, n=10):
    if not isinstance(target_embedding, torch.Tensor):
        target_embedding = torch.tensor(target_embedding)
    all_embeddings = model.embedding.weight
    sims = torch.nn.functional.cosine_similarity(target_embedding.unsqueeze(0), all_embeddings)
    top_scores, top_indices = torch.topk(sims, n)
    results = [(tokenizer.decode(idx), score.item()) for idx, score in zip(top_indices, top_scores)]
    return results

# Convert a prompt into token embeddings (using the lightweight embedding model)
def prompt_to_embeddings(prompt: str):
    tokens = tokenizer(prompt, return_tensors="pt")
    input_ids = tokens['input_ids']
    outputs = model(input_ids)              # shape: [1, seq_len, dim]
    token_id_list = tokenizer.encode(prompt, add_special_tokens=True)
    token_str = [tokenizer.decode(t, skip_special_tokens=True) for t in token_id_list]
    return token_id_list, outputs, token_str

# Pretty‑print helper
def print_tokens_and_embeddings(text: str, max_dims=8):
    token_ids, embeds, tokens = prompt_to_embeddings(text)
    print(f"Sequence length: {len(token_ids)}\n")
    for t_id, t_str, vec in zip(token_ids, tokens, embeds[0]):
        dims = ", ".join([f"{v:.4f}" for v in vec[:max_dims].tolist()])
        print(f"Token ID {t_id:>6} | {t_str!r:>15} | [{dims}, ...]")

print_tokens_and_embeddings("HTML coders are not considered programmers")
# Example (truncated) output:
# Token ID   5835 |         'HTML' | [-0.0186, 0.0009, 0.0110, ...]
# Token ID  54846 | '#programmers' | [-0.0479, 0.0579, -0.0693, ...]

4. Applications

  • Semantic Search & Retrieval: embed queries and passages, retrieve via nearest neighbors (cosine).
  • Clustering & Topic Modeling: group documents in embedding space; visualize with PCA/t‑SNE/UMAP.
  • Recommendations: match users/items using textual or multimodal descriptors.
  • RAG Pipelines: encode knowledge chunks; retrieve to condition an LLM.
  • Bias/Fairness Audits: probe associations encoded in vectors; mitigate with debiasing.
  • Multimodal AI: joint text‑image‑audio spaces enable cross‑modal retrieval and grounding.

5. Challenges

  • Bias: embeddings inherit stereotypes from data; evaluation and mitigation are essential.
  • Interpretability: high‑dimensional geometry is hard to explain; tools are improving but limited.
  • Efficiency: larger dims → more memory/latency; consider pruning, quantization, or smaller models.
  • Domain Shift: contextual models can drift on out‑of‑domain text; consider fine‑tuning or adapters.

6. Conclusion

Embeddings have progressed from statistical term‑weights (TF–IDF) to neural predictive vectors (Word2Vec), to contextual transformer states (BERT/GPT), and now to LLM‑scale representations that power search, RAG, and reasoning. They remain the core bridge between human language and machine computation.
